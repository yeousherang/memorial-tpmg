# 제품 및 요구사항

## 1. 목적

Memorial TPMG의 목적은 한 사람의 삶을 단일한 연대기나 결정 트리가 아니라, 서로 영향을 주는 여러 층의 시간적 상태로 기록하고 탐색하는 것이다.

시스템은 다음 질문에 답할 수 있어야 한다.

- 특정 시점에 어떤 상황, 생각, 감정과 목표가 활성화되어 있었는가?
- 한 선택에 어떤 관찰 가능한 요인과 잠재 요인이 영향을 주었는가?
- 과거 사건에 대한 해석은 시간에 따라 어떻게 바뀌었는가?
- 특정 선택을 바꾸면 어떤 반사실 경로가 생성되는가?
- 현재 행동을 설명할 과거 기억 또는 잠재 요인의 가능성은 어느 정도인가?

## 2. 범위

### 포함

- 다층 노드와 타입이 있는 엣지
- 유효 시간과 기록 시간의 이중 시간 모델
- 확률과 불확실성을 포함하는 노드 및 엣지
- 실제 세계선과 반사실 세계선
- 불변 이벤트 로그와 스냅샷
- 기억의 재해석 버전
- 고스트 잠재 상태와 추론 근거
- 정적 스키마 및 타입 안전 C++ API
- 정적 쿼리 DSL과 하이브리드 최적화기
- 저장, 조회, 순회, 영향 전파와 역추론의 기반

### 초기 버전에서 제외

- 임상 진단 또는 치료 추천
- 인간의 무의식을 객관적 사실로 판정하는 기능
- 자연어로부터 완전 자동 그래프 생성
- 범용 분산 그래프 데이터베이스
- 무제한 길이의 정확한 미래 예측
- GPU 전용 구현
- 안정된 외부 플러그인 ABI

## 3. 사용자와 사용 사례

### 개인 기록 사용자

- 경험과 선택을 기록한다.
- 당시 관점과 현재 관점을 비교한다.
- 선택되지 않은 가능성을 반사실 분기로 탐색한다.

### 연구 및 모델 개발자

- 선택과 반응시간 데이터에 잠재 모델을 연결한다.
- 가설별 고스트 모델을 비교한다.
- 파라미터 및 모델 회복 가능성을 검증한다.

### C++ 라이브러리 개발자

- 도메인 스키마를 타입으로 선언한다.
- 허용되지 않은 관계를 컴파일 타임에 차단한다.
- 데이터 분포에 맞는 저장소와 커널을 선택한다.

## 4. 기능 요구사항

### FR-01: 노드와 레이어

시스템은 최소 다음 레이어를 지원해야 한다.

| 레이어 | 의미 |
| --- | --- |
| WORLD | 외부 사건과 조건 |
| PERCEPTION | 상황에 대한 지각과 해석 |
| COGNITION | 생각, 믿음, 목표와 계획 |
| AFFECT_BODY | 감정과 신체 상태 |
| ACTION | 선택 경쟁과 행동 |
| MEMORY | 사건의 기억 및 재해석 |
| LATENT_GHOST | 직접 관찰되지 않는 잠재 상태 |

### FR-02: 관계

관계는 적어도 `TEMPORAL_NEXT`, `GENERATES`, `ACTIVATES`, `INHIBITS`, `BIASES`, `SELECTS`, `REJECTS`, `CAUSES`, `ENCODES`, `RECALLS`, `REINTERPRETS`, `EVIDENCE_FOR`를 지원해야 한다.

### FR-03: 시간

각 상태는 다음 시간을 구분해야 한다.

- 사건이 삶에서 유효했던 시간
- 시스템에 기록되어 알려진 시간
- 선택적으로 사용되는 주관적 시간 범위

### FR-04: 세계선

- 기본 세계선은 관찰되거나 자기보고된 실제 역사다.
- 분기는 부모 세계선, 분기점, 개입, 가정 및 모델 버전을 가진다.
- 분기 이전 데이터는 공유하고 분기 이후 변경분만 보관할 수 있어야 한다.

### FR-05: 가역성

- 이벤트 재생으로 임의 시점의 상태를 복원한다.
- 역연산 또는 이전 스냅샷과 재생으로 직전 상태를 복원한다.
- 과거 선택에 개입하더라도 기존 세계선을 수정하지 않는다.

### FR-06: 불확실성

- 엣지 존재 확률과 영향 강도 분포를 구분한다.
- 추론된 노드에는 근거, 모델 버전과 신뢰도를 기록한다.
- 반사실 미래는 확정값이 아니라 가능한 궤적의 표본 또는 분포로 표현한다.

### FR-07: 질의

- 시간 단면
- 세계선 제한
- 레이어 및 노드 타입 제한
- 속성 필터와 투영
- 타입이 있는 경로 탐색
- 상위 K개 영향 요인
- 현재 관찰에서 잠재 원인 역추론

## 5. 비기능 요구사항

### 안전성

- 잘못된 노드 ID 조합을 타입으로 차단한다.
- 이벤트 로그는 append-only를 기본으로 한다.
- 읽기 스냅샷은 조회 중 일관성을 유지한다.

### 성능

초기 목표치는 실제 벤치마크 이후 조정한다.

| 항목 | 초기 목표 |
| --- | --- |
| 정적 스키마 검증 | 빌드 시 수행 |
| 노드 ID | 기본 32비트 strong ID |
| 핫 속성 순회 | SoA 연속 접근 |
| 읽기 | 스냅샷 기반 lock-free 또는 최소 잠금 |
| 변경 | append-only delta 저장소 |
| 대규모 정리 | frozen CSR/CSC로 압축 |

### 이식성

- C++23을 기본으로 한다.
- Clang, GCC, MSVC의 최근 안정 버전을 CI 대상으로 한다.
- C++26 기능은 핵심 API에 직접 노출하지 않고 별도 어댑터로 제한한다.

## 6. 윤리 및 해석 제약

- 라이브러리는 임상 진단기가 아니다.
- `INFERRED` 고스트는 사용자의 내면에 관한 확정 사실로 표현하지 않는다.
- 동일 행동을 설명하는 경쟁 가설을 보존할 수 있어야 한다.
- 민감한 개인 기록에는 암호화, 접근 통제 및 삭제 정책을 상위 제품에서 제공해야 한다.
- 연구 데이터에는 동의, 비식별화, 데이터 사전 및 재현 가능한 모델 실행 기록이 필요하다.

## 7. 완료 기준

MVP는 다음 조건을 만족할 때 완료된다.

- 예제 스키마가 세 컴파일러에서 빌드된다.
- 유효하지 않은 엣지와 속성 접근에 대한 compile-fail 테스트가 통과한다.
- 실제 세계선에 의사결정 에피소드를 삽입하고 시간 단면을 조회할 수 있다.
- 한 선택에서 반사실 세계선을 생성할 수 있다.
- frozen/delta 스냅샷에서 동일한 질의 결과가 나온다.
- 이벤트 재생 상태와 역재생 상태가 동일하다.
- 기준 벤치마크와 컴파일 시간 보고서가 생성된다.
