# ADR-0002: 정적 스키마와 런타임 데이터 분리

## 상태

승인됨

## 맥락

TMP로 모든 그래프 데이터를 표현하면 타입 수, 컴파일 시간과 바이너리 크기가 데이터 크기에 따라 폭증한다. 반대로 모든 것을 동적 property graph로 만들면 잘못된 관계와 속성 접근을 런타임까지 발견하지 못한다.

## 결정

노드 종류, 속성, 관계, 레이어 규칙과 쿼리 구조는 타입 수준에서 표현한다. 실제 엔티티, 시간, 확률과 세계선 상태는 런타임 SoA 저장소에 둔다.

## 결과

- 스키마 오류를 컴파일 타임에 발견한다.
- 데이터 크기와 템플릿 인스턴스 수를 분리한다.
- 사용자 정의 스키마는 소스 재컴파일이 필요하다.
- 동적 입력에는 typed command로 변환하는 검증 경계가 필요하다.

## 대안

- 모든 노드를 타입으로 표현: 확장성과 빌드 비용 문제로 제외한다.
- 완전 동적 스키마: 초기 프로토타입에는 가능하지만 코어 계약으로는 제외한다.
